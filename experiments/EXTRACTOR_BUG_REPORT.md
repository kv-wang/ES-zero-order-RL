# 抽取器缺陷报告 — `\boxed{}` 正则无法匹配嵌套花括号 (2026-08-08)

> **修复状态 (2026-08-09)。** 仓库根目录 `ood_eval/answer_extraction.py` 已修复,
> 改用**括号计数**而非正则(见 §9)。测试 `ood_eval/test_answer_extraction.py` 9 组全通过。
> 实测 MATH 训练池保留率 **74.8% → 100.0%**(L3-5 找回 1404 题)。
> 活跃 try `2026-08-08_momentum_axis` 的 2 处已于其六 arm 跑完后同步;
> 四个归档 try 的 11 处**刻意不改**,理由见 §9。

**结论：`ood_eval/answer_extraction.py` 的 `BOXED_RE` 与 `es_bench/data_math.py` 的 `_BOXED`
使用同一个无法匹配嵌套花括号的正则。这同时污染了训练奖励和评测指标，影响四个 try 的
全部数学任务数字，以及 ES 与 GRPO 两侧。Countdown 不受影响（它用自己的 reward）。**

来源实验：Exp-1（校准测量工具）。执行者：Claude Code 会话 2026-08-08。

---

## 1. 缺陷

```python
# ood_eval/answer_extraction.py:5  和  es_bench/data_math.py:15  （两处字面相同）
BOXED_RE = re.compile(r"\\boxed\{([^{}]+)\}")
```

`[^{}]+` 显式排除花括号，因此任何含嵌套结构的 boxed 答案都无法匹配：

| 输入 | 命中 |
|---|---|
| `\boxed{18}` | `18` |
| `\boxed{-3}` | `-3` |
| `\boxed{\frac{1}{2}}` | **MISS** |
| `\boxed{\sqrt{3}}` | **MISS** |
| `\boxed{x^{2}}` | **MISS** |
| `\boxed{2\sqrt{5}}` | **MISS** |
| `\boxed{\text{even}}` | **MISS** |

## 2. 评测侧：结构性不可评分题

抽取是三级级联（`answer_extraction.py:25-38`）：

1. `\boxed{...}` — 受上述缺陷影响
2. `FINAL_ANS_RE`，字符类 `[-+*/().,\w\\]+` — **不含花括号**
3. `NUMERIC_TAIL_RE` `(-?\d+(?:\.\d+)?)\s*$` — 纯数字兜底

**三条路径都不可能产出含 `{` 的字符串。** 因此凡是 gold 含花括号的题，无论模型输出什么，
`exact_match` 恒为 0。这是解析层面的结构性失败，不是模型能力问题。

实测（base-axis pilot，vanilla seed0）：

| 数据集 | n | gold 含花括号 | 占比 | 该子集正确率 |
|---|---:|---:|---:|---:|
| math500 | 300 | 62 | 20.7% | **0.000** |
| olympiadbench | 300 | 102 | 34.0% | **0.000** |
| minerva_math | 272 | 68 | 25.0% | **0.000** |
| svamp | 300 | 0 | 0% | — |
| gsm8k | 300 | 0 | 0% | — |

232 道题全部为 0，与解析式推导一致。

## 3. 训练侧：训练池被静默过滤

`data_math.py:24-26` 的 `_math_gt` 用同一正则从 solution 抽 gold，抽不到返回 `None`，
`load_pool` 随即 `continue` —— **题目被静默丢弃，不留任何日志**。

用本地缓存的 `EleutherAI/hendrycks_math` train split 实测（对比允许一层嵌套的修复版正则）：

| 池 | n | 当前正则保留 | 修复后可保留 | 静默丢弃 |
|---|---:|---:|---:|---:|
| MATH train 全集 | 7500 | 5772 (77.0%) | 7399 (98.7%) | 1627 (**21.7%**) |
| L3-5（实际训练用） | 5586 | 4180 (74.8%) | 5497 (98.4%) | 1317 (**23.6%**) |

后果不只是池子变小：**保留下来的题系统性偏向数值型答案**，符号型答案（分数、根式、
表达式）几乎被整体剔除。训练分布与评测分布因此不一致——训练只见数值答案，
评测集里却有 20–34% 需要符号答案，且那些题还恰好无法被评分。

## 4. 影响范围

- 四个 try 的 `ood_eval/answer_extraction.py` **md5 完全相同**（`26f589622314d1cad0d9bb3dbf78e8f3`）。
- `es_bench/shared_reward.py` 的文档写明它是 "imported by BOTH the ES trainer and the GRPO
  (verl) control"，所以**训练奖励和评测、ES 和 GRPO 两侧同时受影响**。
- **Countdown 不受影响**：`countdown/countdown_task.py` 用自己的 `answer_regex`，
  从不经过这个抽取器。

## 5. 对既有结论的影响（分开说，避免过度解读）

**不受影响的：** 配对 McNemar 比较。McNemar 只计入分歧对，而结构性不可评分题对两个 arm
恒为"都错"（concordant），本来就被自动排除。实测验证：剔除这些题前后 z 值**逐位相同**
（见 §6 表）。所以此前所有基于配对检验的 arm-vs-arm 结论仍然成立。

**受影响的：**
- 所有报出的**绝对准确率**在 math500 / minerva / olympiad 上被系统性压低。
- **OOD-avg** 这个合成标量、以及任何 arm-vs-base 的边际比较。
- **训练侧的 fitness 信号**：训练池少了 23.6%，且分布有偏。

**一个值得检验的假设（尚未验证）：** 本程序的核心谜题是 split-half ρ 在 countdown 上
0.51、在数学上 ≈0.06。而 countdown 是唯一不经过这个抽取器的任务。训练池被过滤 23.6%
且偏向数值答案，是否是数学侧 fitness 信号弱的部分原因，值得作为独立实验检验。
**不要在验证前把这当结论。**

## 6. 附带发现

- **tier-3 兜底不可区分。** `NUMERIC_TAIL_RE` 抓取末尾数字并记为 `success=True`。
  在 `max_tokens=512` 截断的长推理里，这可能抓到中间计算的无关数字。
  `shared_reward.py:53` 计算了 `used_boxed` 但 `eval_core.py:88` 未写入 perq 文件，
  因此 artifacts 里**无法区分 tier-1 与 tier-3 抽取**。建议持久化 `used_boxed`。
- 抽取器本身**没有**"永远返回值"的假成功问题：无命中时 `success=False`，诚实。
  此前怀疑的"兜底回退导致 extract_rate=1.00"不成立——那是分析脚本把布尔 `False`
  误判为已抽取所致，非代码缺陷。真实 extract_rate 为 svamp 0.983 / math500 0.780 /
  olympiadbench 0.713 / minerva 0.577，与 track_b 独立报告的 0.68 / 0.58 吻合。

## 7. 建议动作

1. **修正两处正则**为允许一层嵌套：`r"\\boxed\{((?:[^{}]|\{[^{}]*\})*)\}"`
   （实测可把 MATH train 保留率从 77.0% 提到 98.7%）。两处必须同步改，
   且四个 try 的副本都要改，否则跨 try 结果不可比。
2. **持久化 `used_boxed`** 到 perq，使 tier-1/tier-3 可分。
3. **重跑受影响的评测**。因为配对结论未受影响，优先级排在 Exp-4 之后即可；
   但任何**对外发表的绝对准确率**必须重跑后才能用。
4. **重新审视训练池**：修复后 L3-5 池从 4180 增至 5497，训练数据分布改变，
   历史训练曲线不可与修复后的直接比较。

## 9. 修复 (2026-08-09)

### 采用的方案:括号计数,而非"允许一层嵌套"的正则

§7 原本建议把正则改成 `r"\\boxed\{((?:[^{}]|\{[^{}]*\})*)\}"`。**没有采用**——因为上游
`VsonicV/es-at-scale` 的 `es_at_scale/reward_function/math_grader.py::last_boxed_only_string`
已经有一个正确实现,用手工括号计数,**支持任意深度嵌套**。移植它比自造正则好三点:
任意深度而非一层;是论文作者本人的实现,后续对齐论文数字时口径一致;
`\boxed{\frac{\sqrt{2}}{2}}` 这类两层嵌套也能处理。

新实现见 `ood_eval/answer_extraction.py` 的 `_last_boxed` / `_boxed_content_at`。
相对上游有两处**有意偏离**,均在代码注释中记录:

1. 上游只看最后一个 `\boxed`,若它不闭合就放弃。这里**从后往前逐个尝试**,
   所以被 token 上限截断的回答仍能落在它最后一个完整的 box 上,而不是掉进数字兜底。
2. 上游的 `remove_boxed` 断言前缀必须是 `\boxed{`,因而对 `\fbox{...}` 返回 None,
   尽管它自己的扫描器接受 `\fbox`。这里两个命令一视同仁。

### 实测效果

| 池 | n | 修复前保留 | 修复后保留 | 找回 |
|---|---:|---:|---:|---:|
| MATH train 全集 | 7500 | 5772 (77.0%) | **7498 (100.0%)** | +1726 |
| L3-5(实际训练用) | 5586 | 4180 (74.8%) | **5584 (100.0%)** | +1404 |

剩余 2 题是 solution 里根本没有 `\boxed` 的样本,与本缺陷无关。

评测侧:math500 / minerva / olympiadbench 中 gold 含花括号的 20.7% / 25.0% / 34.0%
从"结构性恒判 0"变为**可评分**。但具体有多少会判对,**必须重跑评测才知道**——
见下面的双向性说明。

### 一处会降低分数的行为改变(有意保留)

当回答里 boxed 内容与文末 `Final answer: X` **不一致**时:

```
输入: \boxed{\frac{1}{2}}  Final answer: 0.5
旧: tier-1 失配 → 落到 tier-2 → 抽出 "0.5"
新: tier-1 命中 → 抽出 "\frac{1}{2}"
```

若 gold 恰为 `0.5`,旧代码是**蒙对**,新代码判错。语义上新行为正确(模型 box 出来的
就是它的答案),故予以保留,并在 `test_answer_extraction.py` 第 8 组钉死为有意决策。

**含义:修复会让个别题目在两个方向上移动,不能假设分数只升不降。** 这正是必须重跑
评测、而不能对旧结果做修正估算的原因。

### 为什么无法对已有结果重新打分

`eval_core.py` 写入 perq 的字段是 `gold` / `correct` / `extracted`(布尔) / `level`,
**没有保存模型的原始回答,也没有保存抽出的字符串**。因此已有的评测结果无法离线重打分,
只能重跑生成。建议下一轮把 `extracted` 的**字符串值**和 `used_boxed` 一并落盘。

### 修复范围:只改了两处,其余刻意不改

| 副本 | 处理 | 理由 |
|---|---|---|
| `ood_eval/answer_extraction.py`(仓库根) | **已修** | 规范源;新 try 从这里继承 |
| `experiments/2026-08-08_momentum_axis/`(2 处) | **已修**(2026-08-09 21:09 六 arm 跑完之后) | 活跃 try;运行期间不改,以免 6 个 arm 评测口径不一致 |
| `2026-07-18` / `2026-07-21` / `2026-07-23` / `2026-07-24`(共 11 处) | **不改** | 按 `experiments/README.md` 的约定,每个 try 是冻结快照,必须能复现**自身**的结果。改了代码而不重跑结果,该 try 就再也无法自洽 |

`2026-08-08_momentum_axis` 是唯一一个代码与结果不自洽的 try:它的六个 arm 结果产生于
修复之前,而代码已在其后修复,故**重跑不会复现其数字**。该 try 的 `FINAL_REPORT.md`
顶部已加醒目标注,并记录了还原缺陷版所需的 md5(`26f589622314d1cad0d9bb3dbf78e8f3`)。
这是有意的取舍:让后续在该 try 内的运行用上正确抽取器,优先于保持它自身可复现。

因此**归档 try 的绝对准确率数字永久带有此缺陷**,这是既成事实,只能通过在新 try 里
重跑来获得可用数字。它们的**配对结论仍然有效**(不可评分题对所有 arm 恒为 concordant,
McNemar 自动排除,已实测验证 z 值逐位不变)。
