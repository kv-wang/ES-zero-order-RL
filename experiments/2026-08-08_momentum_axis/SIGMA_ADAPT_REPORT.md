# 自适应 σ — 终版报告 (2026-08-11)

**结论:NEGATIVE,但属于"干净的否定"。** 控制律确实被执行到了(σ 在带内自由移动、
一次未贴 clip),但它既没有改变成员的可分辨性,也没有带来任何准确率变化。
**否定的范围有限**——实测表明 [0.5σ₀, 2σ₀] 这个量程跨不过奖励的离散档位,
因此任何在此量程内的控制律都会得到同样的 null。

判读标准冻结于运行之前:[PREREG_SIGMA_ADAPT.md](PREREG_SIGMA_ADAPT.md)。

## 问题

用户提出:**ES 的"梯度"越大,扰动的 σ 越大**,α 保持不变。这样做能否改善
MATH L3-5 上的 ES?

## 设置

| | |
|---|---|
| 对照臂 | `vanilla_N16_s{0,1}` — 固定 σ=1e-3 |
| 处理臂 | `sigadapt_N16_s{0,1}` — 同上 + `--sigma_adapt` |
| 控制律 | `σ_t = σ₀·clip((fs_ema/fs_ref)^1.0, 0.5, 2.0)`,因果,EMA β=0.9,前 10 步标定 `fs_ref` |
| 信号 | `fitness_std`,数学上即 ES 梯度范数(`‖ĝ‖ ≈ √(d/N)·std(f)/σ`) |
| 其余 | Qwen2.5-Math-1.5B-Instruct、MATH L3-5、B=8、α=5e-4、fp16、CRN、N=16、200 步、修复后抽取器 |
| 运行 | tmux `sig`,2026-08-10 21:25:34 – 2026-08-11 02:19:23,4 臂全 rc=0,每臂约 4407s |

**为何选 `fitness_std` 而非用户原本提议的 `Σ_k a_k(z₊−z₋)/N`**:后者只存在于探针臂,
vanilla 里没有;且 52–65% 的步恰好为 0。`‖Δ‖` 更不可用——被 z-score 钉成常数
`α√(d/N)`,实测变异系数 0.0001。

## 结果

### 第一步:控制律被真正测试了(预注册情形 3)

```
sigadapt/s0: mean=0.928  min=0.635  max=1.245   贴下界 0/195  贴上界 0/195
sigadapt/s1: mean=0.878  min=0.559  max=1.271   贴下界 0/195  贴上界 0/195
```

σ 全程在带内移动,**一次未触界**。所以这不是"clip 卡住导致没测成"。

均值 0.88–0.93 **小于 1**,方向与预注册的推测一致:零更新步(约 21%)把 `fs_ema` 拉低、
σ 随之收缩。自反馈存在,但幅度不足以跑到下界。

### 第二步:可分辨性纹丝不动 —— 这是核心发现

vanilla 无探针对,故用**成员适应度的不同取值数**作为打平率的等价指标:

| 臂 | 不同取值数(中位/均值) | 零更新率 |
|---|---|---|
| vanilla/s0 | 2.0 / 2.34 | 0.169 |
| vanilla/s1 | 2.0 / 2.22 | 0.221 |
| sigadapt/s0 | 2.0 / 2.28 | 0.210 |
| sigadapt/s1 | 2.0 / 2.24 | 0.215 |

**16 个成员的适应度中位数只有 2 个不同取值,四臂完全一致。** 自适应没有改变任何东西。

根因是量化:B=8 时奖励只有 9 个档位,而 σ 在 [0.56σ₀, 1.27σ₀] 内的变化**跨不过一个档位**。

尽管是不同脚本、不同输出目录、相隔一天。两轮 vanilla 因此可合并为 4 个 seed。

## 一处在运行前更正的推导错误

PREREG 初版写道"有效学习率 `α·σ_t` 随 σ 同比变化,故半径与步长混淆"。**该判断是错的**,
已在数据产出之前更正:

σ 根本不出现在更新式里(`gauss_coeffs = (α/N)·z`,提交时加的是原始 `ε` 而非 `σε`),
故 `‖Δ‖ ≈ α√(d/N)` 与 σ 无关。更根本地,线性区内 `f_i−f̄ ≈ σ⟨g,ε_i⟩`、`std(f) ≈ σ‖g‖`,
于是 `z_i ≈ ⟨g,ε_i⟩/‖g‖` —— **σ 在 z 里被精确约掉,一阶效应为零**。

这反而使实验更干净:两臂步长本就相同,半径是唯一变量,不需要补偿臂。
也正因如此,**打平率/可分辨性才是比准确率更靠前的判读指标**——这条在运行前补进了预注册。

## 局限与未解决项

**量程可能根本不够。** 这是最重要的一条。σ 只在 [0.56σ₀, 1.27σ₀] 移动过,而奖励档位间距
是 1/8。**本实验没有测试过更大的 σ 变化**,所以不能断言"σ 自适应无效",只能说
"这个量程内无效"。

**背景是 ρ≈0。** 2026-08-10 标准轮首次测得本 regime 的 split-half ρ 中位数为 0,
成员排名是纯抽样噪声。若如此,`fitness_std` 的波动大概率也主要是噪声,控制器本质上
在追噪声——`sigma_ratio` 高频抖动而无系统趋势(0.56↔1.27)正符合这一图像。
**但这未经独立验证。**

**双 seed。** 未满足预注册的 3-seed 规则。以观测到的效应量,即使补到 3 seed 也大概率仍是 null。

**方向问题未被回答。** 预注册推测"应当负相关"(σ 小时才该放大)。本轮 σ 均值小于 1
且无效果,既不能证实也不能证伪该推测——因为整个量程内什么都没发生。

**只测了 vanilla。** 未在探针臂(momentum/baseaxis)上试,那里有真正的打平率可直接观测。

## 下一步

**不要调 gain。** 在量程未知时调增益是在两个未知量上同时动手。

正确的顺序是先做 **σ dose-response**:固定 σ ∈ {0.25, 0.5, 1, 2, 4}×σ₀ 各跑一轮,
测"不同取值数"和零更新率随 σ 的变化。那条曲线会直接回答:

1. 多大的 σ 变化才能让可分辨性动起来 → 给出闭环控制的可用量程
2. 是否存在一个 σ 使打平率显著下降而 KL 不失控 → 是否值得做闭环
3. 若曲线全程平坦 → σ 不是这个 regime 的瓶颈,整条线可以关掉

这也正是台账里 P2 那条"B1 σ dose-response 补完"——它本来就是任何 σ schedule 工作的前提。

**更根本的**:若 ρ 确实为 0,那么 MATH L3-5 上任何基于成员排名的改动都不会有效。
台账 P0 的两条(搬到 countdown、把 B 从 8 提到 200)优先级高于继续在此 regime 上调 σ。
