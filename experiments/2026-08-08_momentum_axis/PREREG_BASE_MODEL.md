# 预注册:把基座模型从 `-Instruct` 换成 `Qwen2.5-Math-1.5B` (2026-08-14)

写于正式运行之前。任何在结果出来之后才加进来的分析,必须在本文件中显式标为"事后"。

## 为什么换

到 2026-08-13 为止,本 try 的**全部**结果跑在 `Qwen2.5-Math-1.5B-Instruct` 上。该模型本身
就是 GRPO 的产物(72B 奖励模型 + 迭代 rejection sampling + GRPO,arXiv:2409.12122)。
因此 [BASE_VS_TRAINED_REPORT](BASE_VS_TRAINED_REPORT.md) 无法区分两个互相竞争的解释:

- H1:**从一个已被优化到局部最优的点出发**,做无方向移动,期望收益为负("窄靶")
- H2:训练本身有害

基座版是能把这两者分开的对照组。它也是 ES 论文数学实验用的类型
(论文用 `Qwen2.5-Math-7B`,**基座版**,见 [JULY_CONFIG_AUDIT](../JULY_CONFIG_AUDIT.md))。

这个 `-Instruct` 值当初是**快照拷贝继承来的、从未被复查**——2026-08-09 从 07-23 的 try
拷贝而来,四天后审计才发现。它不是一次有依据的选择。

## 换了什么

| 项 | 旧 | 新 |
|---|---|---|
| `config.MODEL` | `Qwen/Qwen2.5-Math-1.5B-Instruct` | `Qwen/Qwen2.5-Math-1.5B` |
| 结果目录 | `results/<arm>` | `results/<arm>_base`(由 `config.RESULTS_SUFFIX` 决定) |
| 采样 | 无 `stop` | `stop=["<|im_end|>","<|endoftext|>"]` |

**其余全部不变**:MATH L3-5、TRAIN_SIZE=2000、DATA_SEED=1234、B=8、σ=1e-3、α=5e-4、
200 步、N=16、fp16、CRN、六套评测电池、cap 300、max_tokens 2048、修复后的抽取器、
GRPO 按总生成次数对齐(400 步 × 64 rollouts = 25,600 = 一个 ES 臂)。

## 运行前已测到的事实(2026-08-14,60 题 MATH L3-5,贪心,512 token)

这些是**运行前**的观测,记录于此以免事后被当作发现:

| | 撞 512 上限 | 含 `\boxed{` | 抽取成功 | 正确 | acc |
|---|---|---|---|---|---|
| **Math-1.5B(基座)** | 49/60 | 30/60 | 10/60 | 7/60 | **0.117** |
| Math-1.5B-Instruct | 35/60 | 27/60 | 27/60 | 19/60 | 0.317 |

基座版在多数题上**回显提示词并陷入循环**(典型尾部:`... \boxed{}. Sgt\nSolve \[...\]`
不断重复)。30 个含 box 的回答里有 20 个**只含提示词里那个空 box**,没有真答案。

生成在跨进程、跨 `gpu_memory_utilization` 下均可复现(60/60 逐字相同),所以上表不是噪声。

**这意味着 0.117 这个起点里混有截断伪影,不能读作"基座版的数学能力"。** 它同时也落在
论文全部实验的起点区间(0.1%–31.2%)内,而 `-Instruct` 的 0.645 不在。

## 预测与判据

**主假设 H-base:在未经 RL 的基座上,训练的期望收益为正**(与 `-Instruct` 上测到的
七臂全负相反)。若成立,则 BASE_VS_TRAINED 的"窄靶"机制被确认为**局部最优点特有**,
而非训练的普遍性质。

判据(ID = MATH-500 L3-5,对基座逐题配对):

- **GO(H1 得到支持)**:≥5/7 个训练臂 ID 高于基座,且符号检验 p<0.05。
- **NEGATIVE(H2 得到支持)**:≥5/7 个臂 ID 低于基座 → "窄靶"解释不成立,需另找机制。
- **INCONCLUSIVE**:方向混杂,或下面任一失效条件触发。

**失效条件(任一触发则本轮不产出关于 H1/H2 的结论,只产出一份诊断)**:

1. **训练信号退化**:ES 的 `pair_tie_rate` > 0.90(在 `-Instruct` 上是 0.64–0.75)。
   打平率过高意味着成员适应度几乎全同,z 打分放大的是纯噪声。
2. **截断主导**:任一臂在 MATH-500 上 `extract_rate` < 0.80。
   低于此值时准确率衡量的是"有没有写完",不是"对不对"。
3. **基座起点过低**:基座 ID < 0.05。此时下限效应使配对检验失去分辨力。

失效条件 1 和 2 是**运行前就认为很可能触发的**——上表显示基座抽取率约 10/60。
明确记录:**如果触发,这不是意料之外的结果,而是本次配置的已知风险。**

## 修订 (2026-08-14,正式运行之前):改用 few-shot 提示词

上文预登记的失效条件 2 在**预跑冒烟中就已触发**,且比预期严重。10 步 N=8、eval cap 40 的
基座版冒烟六套抽取率:

| | math500 | svamp | gsm8k | minerva | olympiad | amc23 |
|---|---|---|---|---|---|---|
| 抽取率 | 0.725 | **0.35** | 0.725 | 0.825 | 0.825 | 0.80 |
| acc | 0.425 | 0.275 | 0.475 | 0.075 | 0.125 | 0.40 |

SVAMP(最简单的一套)有 65% 的回答抽不出答案。这些准确率衡量的是**格式遵从度**,不是数学能力。
训练侧更糟:512 token 预算下抽取率约 0.17,即约 83% 的 rollout 无论对错都得 0 分,
ES 的适应度实际在度量"有没有在预算内写完"。

因此在正式运行前修订协议:**基座模型改用 4-shot 纯文本提示词**
(`data_math.build_prompt`,由 tokenizer 的 eos 自动路由)。理由是基座模型需要被**演示**
答案格式而非被**描述**,这也是 Qwen 官方报告与 ES 论文评测基座模型的做法。

- `-Instruct` 走原 ChatML 零样本路径,**逐字不变**,已冻结的各臂结果仍可复现。
- 基座版提示词从 50 token 增至 236 token。这是每次生成的固定成本,已知并接受。
- `C.STOP` 增加 `"\nProblem:"`,因为 few-shot 格式的回合边界是下一个样例的开头而非特殊 token。

**这是一次协议偏离,记录在案:** 基座版各臂与 `-Instruct` 各臂现在有**两个**变量不同
(模型 + 提示词格式),因此两组之间**不可直接做配对比较**。基座组内部
(base 参考 / GRPO / vanilla / baseaxis / momentum)共用同一提示词,组内比较仍然有效——
而这正是本轮要回答的问题。

若 few-shot 后抽取率仍 < 0.80,则不启动正式运行,只产出诊断。

## 其他已知会削弱本轮结论的因素

**512 token 训练预算对基座版偏紧。** 82% 的样本被截断。提高预算会同时改变 ES 与 GRPO 的
生成成本,破坏已对齐的总生成次数预算,故本轮不改。

**仍是 2 seed**,低于本项目预注册的 3 seed 规则。

## 冻结的对照

`-Instruct` 各臂的结果(2026-08-09 ~ 08-13)保留在原 `results/<arm>` 目录中,不重跑、不覆盖。
`RESULTS_SUFFIX` 保证新旧不互相顶掉——若无此机制,"summary 已存在则跳过"的逻辑会把旧模型
的结果当成新模型的报出来。
