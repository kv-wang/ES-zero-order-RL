# vanilla ES 与论文方法的逐条核对 (2026-08-14,零 GPU)

**结论:算法实现与论文 Algorithm 2 完全一致——扰动、种群、z 打分、更新公式逐条对得上,
论文明确排除的四项增强(mirrored sampling / rank transform / weight decay / Adam)代码里
一项都没有。但三个超参数全部远低于论文,其中最关键的是**每个成员的奖励批量 B=8,
而论文用的是整个训练集**(Sudoku 实验明写 800)。split-half ρ 恰恰是"B 是否足够大"的度量,
本仓库测到 ρ≈0,与这个 100 倍的差距直接对应。**

## 问题

本仓库的 vanilla ES 与 [ES 论文 arXiv:2509.24372](https://arxiv.org/abs/2509.24372) 是否一致?
若一致,为何论文报告大幅提升而本仓库测到零效应?

## 方法

从论文 PDF 抽取 Algorithm 1、Algorithm 2 与各实验的超参数段落(v3,29 页);
逐行比对 [es_train_axis.py](es_bench/axis_probe/src/es_train_axis.py) 的训练循环与
[es_worker.py](es_bench/es_worker.py) 的扰动/更新实现。

## 算法层面:逐条一致

| 论文 Algorithm 2 | 本仓库实现 | 一致? |
|---|---|---|
| 3: 采样 N 个随机种子 | `gauss_seeds = [prng.randrange(...) for _ in range(n_gauss)]` | 是 |
| 6-10: 用种子重置 RNG,逐层采 ε∼N(0,I),就地 θ+σε | `es_set_member`:`gen.manual_seed(seed)`;`torch.randn`;`base + sigma*noise` | 是 |
| 11: R_n = R(扰动后的 θ) | `member_primary()`,`temperature=0.0` | 是(论文亦为贪心) |
| 12-16: 用同一种子重放并减回 | 保留 `_es_base` 副本直接覆写 | **数学等价,数值更好**(不累积舍入) |
| 18: z 打分 Z_n=(R_n−R_mean)/R_std | `z = (f - f.mean()) / (f.std() + 1e-8)` | 是(多了 1e-8 保护) |
| 20-24: θ_t ← θ_{t−1} + α·(1/N)·Z_n·ε_n | `gauss_coeffs = (alpha/N)*gauss_z` → `es_commit_update` 累加 | 是 |

更新公式两边都是

```
θ ← θ + (α/N) · Σ_n z_n ε_n
```

**σ 不出现在更新式中**——它只决定扰动半径,在 z 打分时被约掉。这与本仓库 08-11 那轮
更正过的推导一致(当时先误写成"有效 LR = α·σ",实测 ‖Δ‖ 与 σ 无关后更正)。

论文第 3 节明写:*"rank transformation of rewards, mirrored sampling, weight decay, and
virtual batch normalization are not used in this work. Additionally, we do not utilize more
advanced optimizers like Adam."* 本仓库 vanilla 臂这四项**同样一项都没有**。
(base-axis 与 momentum 是本仓库自加的变体,不属于论文方法,不在本次核对范围。)

## 超参数层面:三项都低于论文

| 参数 | 论文 | 本仓库 | 比例 |
|---|---|---|---|
| σ | 0.001 | 0.001 | **一致** |
| α | 5×10⁻⁴(= σ/2) | 5×10⁻⁴ | **一致** |
| 种群 N | **30**(Sudoku 32、ARC-AGI 50) | **16** | 0.53× |
| 迭代数 | **500**(数学基准)~2500(Sudoku) | **200** | 0.4× ~ 0.08× |
| **每成员奖励批量 B** | **整个训练集**(Sudoku 明写 800) | **8**,且每步重抽 | **~0.01×** |

σ 与 α 精确命中,包括论文那条 α=σ/2 的关系。问题全在另外三项。

**N=16 是论文自己的消融里测过的最低值,也是表现最差的一档:**

| N | 16 | 30 | 64 | 128 |
|---|---|---|---|---|
| pass@1(某任务) | 0.697 | 0.714 | 0.725 | 0.727 |
| pass@1(3B / GSM8K) | 0.807 | 0.823 | 0.804 | 0.831 |

## B 才是决定性的那一项

论文 Sudoku 实验原文:*"trained with greedy decoding and **batch size set to the entire
800 sample training set**"*。即每个成员的 R_n 是在 800 道题上的平均。

本仓库:`step_batches = [[drng.randrange(len(train)) for _ in range(B)] ...]`,B=8,
且**每步重新抽取**。两处差别:

**一、适应度分辨率。** B=8 的二元奖励只能取 9 个值,实测 16 个成员只占用其中约 3 个,
于是大面积并列,z 打分后的排名主要由"谁恰好落进同一档"决定。B=800 时可取 801 个值,
成员之间几乎不会并列。**split-half ρ 正是这件事的度量**——本仓库四个 ES 臂 ρ 中位数
精确为 0,而 07-30 countdown(B 更大、奖励连续)是 0.51。

**二、目标函数是否稳定。** 论文每次迭代用同一个固定集合,ES 在优化一个**不动的**目标;
本仓库每步换一批题,目标函数本身在移动,成员之间的适应度差里混入了"这一批题恰好难/易"。

## 含义

**本仓库的零效应不能读作"论文方法无效"。** 算法是对的,跑的是论文没有测试过的参数区域:
B 小 100 倍、N 取论文消融里最差的一档、迭代数少 2.5~12 倍。三者都朝同一方向压低信噪比。

**这也重新解释了此前几轮的 null。** 08-09 的 A1(动量轴)、08-11 的 σ 自适应、
08-14 的基座版五臂,全部在 B=8 下进行。台账 P0 的"B: 8→200"此前被当作一个优化项,
现在应当重新定性为**回到论文配置**。

## 限制与未解决

**论文没有为数学/推理基准明确给出 B。** "batch size = 整个训练集"这句只出现在 Sudoku 一节;
Countdown 的微调集据 Table 5 仅两个样例;数学基准那节只说了 N/σ/α/迭代数与
"200 samples 用于训练期监控准确率、2000 用于测试",未说明每成员奖励用多少题。
因此"论文一律用全训练集"是**从一个实验外推的**,并非全文通例。

**未做 B 的对照实验。** 本文的因果链("B 小 → ρ≈0 → 无效")依据是:①本仓库测得 B=8 时
ρ≈0;②07-28 overnight 测得 B=200 时 ρ=0.31–0.46。但那两次在不同配置下进行,
**未在同一 regime 内做过 B 的扫描**。

**提高 B 不是免费的。** 总生成次数 = steps × N × B。当前 200×16×8 = 25,600
(与 GRPO 对齐的预算)。若 B 提到 200 且保持 N、steps 不变,是 25 倍算力;
若保持总预算,steps 只剩 8 步,无意义。**要复现论文配置必须重新申请预算,
或在 B、N、steps 之间重新取舍**——这是一个真实的设计决策,不是调参。

**迭代数差距未单独评估。** 论文数学基准跑 500 步,本仓库 200 步。
即使 ρ 修好,200 步是否足够仍未知。台账已有一条"countdown 跑满 500 步"的 P2。

**base-axis 与 momentum 不在核对范围。** 二者是本仓库自加的变体,论文没有对应物,
其与论文的偏离是设计意图而非缺陷。
